## Done

- [chore] Google Form → order-type tagging: resolved by hard-coding the type in the dedicated form's Apps Script, NOT in the app. Investigation (session 2026-07-22) found order type is not form-determined in the data — the `GF` prefix / `[via Google Form]` note is shared across multiple forms and holds both `NY Route` and `Self-distro`; `PU` (`[via Google Form Pickup]`) holds `Distributor` + `Self-distro`; the same customers appear under multiple forms. So there is no unique per-form signal in stored orders and no app-side auto-tag can separate them. Decision: dedicated forms (e.g. the CT/NY/NJ = NY Route form) stamp `order_type` directly in their bound script, and use a UNIQUE `ID_PREFIX` (NY Route = `NYR-`) so IDs don't collide with the shared-`GF` forms under merge-duplicates. An app-side prefix→type config UI was built (v185) then reverted (commit `20ca2c1`) as the wrong model for this data.
- [feature] Fulfillment: allocate an order line across multiple lots + produce-from-source inline. The fulfill modal now has one unified per-line lot picker listing both existing finished-good lots ("in stock") and the flavor's source/bin lots ("make from …", produced on the fly at ship time inheriting the lot #). Click "Add lot" to split a line across several lots. No auto-seeding — the user explicitly picks every lot that ships (recall traceability). Rough/approximate counts warn but don't block (`findBackfillChain` no longer requires a single source lot to cover the whole line; the hard over-draw block is now a warning). Reuses the existing production/allocation engine (Phase A generalized from one backfill to N). Shipped v183, helpContent v8; user validating in production (existing-lot-only, bins-only, mixed, multi-lot split, over-pull cases).
- [feature] Inventory CSV export — by SKU or by lot. The Inventory Export button is now a dropdown: "By SKU" emits the original one-row-per-item list (Qty = item total); "By SKU + Lot #" emits one row per lot for lot-tracked items where the `Qty` column holds that lot's own quantity, plus `LotNumber`, `ProductionDate`, and `LotLocation` columns. Items with no lots export as a single row with the item Qty and blank lot fields; zero-qty lots are skipped. The By-SKU shape is unchanged, so the column-mapped CSV import still round-trips. App v182, helpContent v7.

- [feature] Help Genie — Phase 2: Haiku conversational fallback. When static search finds no confident match, the question is sent to a Vercel serverless function (`api/genie.js`) that asks Claude Haiku (`claude-haiku-4-5`) using the same knowledge base as a prompt-cached system block; confident static matches still answer instantly and free. Available to all signed-in users. Read-only by construction — the endpoint has no tools, no DB, text-out only, and the system prompt forbids claiming to make changes. API key (`ANTHROPIC_API_KEY`, marked Sensitive) lives only in Vercel env; cost guarded by an Anthropic Console spend cap. Frontend shows a typing indicator and degrades gracefully to static suggestions if the endpoint is unreachable. New file `api/genie.js`; `@anthropic-ai/sdk` dependency; `GenieHelp.jsx` → v2. (Live Haiku path verifiable only on the Vercel deploy.)
